# R2.4 additions

The recorded session now resolves the same effective defaults as the stock configuration writer (including 30 game FPS), reads the selected driver's bounded metadata in either process, and snapshots refresh-recovery/native-sampling counters. Explicit Send log reads at most the last 1 MiB of a timestamp-matched renderer log and emits an aggregate observation summary: last upscaler path, largest reported interval, maximum per-report shown-late count, last reported FG lead and observed native-rate transitions. Missing data stays unavailable. These counters are not summed into dropped-frame rates or advertised as measured input latency. No continuous log tailer, new exporter or performance history is introduced.

The original preparation panel transitions to Loading game after warming until a positive native FPS observation, a 20-second deadline, or disabling statistics. The panel passes input after preparation. FPS Off does not force native statistics collection for this status. All native sampling is single-flight on a worker and stale results are rejected after pause/destroy. These observations do not create a save or change native game shutdown.

# R2.3 session details and exit feedback

The existing Send log action keeps its original chooser, native attachments and read grants. Its provider whitelist adds exactly one file, `session-details.txt`; private metadata and saves remain inaccessible through that provider. Sharing prepares the additional file off the UI thread and then calls the original share method. A metadata failure falls back to the original logs. A fresh installation without original log/status files still shows the stock No log yet message.

The shared file labels current launcher settings separately from the last recorded game session. It includes the installed app version, Android/device model, selected graphics values and driver, last foreground Android refresh observation, final session phase, bounded native GPU information and available engine resolution/FG/refresh reports. Native-log observations are included only when file timestamps fit the captured session window; this is a timestamp check, not a session identifier supplied by the closed engine. Android's reported display mode is not a physical frame-timing measurement.

Session snapshots are event driven (start, resume, focus, display-mode change, pause and stop). They replace a single private file and are captured only when Logging was enabled for that game launch. Logging Off clears the previous snapshot on the next launch. Send log can still generate current settings when explicitly requested while logging is off, and labels missing session data. No arbitrary preference dump, game path, save data, account token, new exporter, history or performance preset is added.

Return to launcher still releases input and uses normal Activity/SDL shutdown. Before finishing the game activity it brings the existing launcher forward with a private pending-exit marker. The launcher shows its existing themed dialog with Closing game… while a background watcher probes the same dedicated OS file lock used by the engine and save manager. The watcher never unlocks another owner's lock, kills the game, or creates a manual save. The game continues to retain its lock until the SDL thread has ended. Once the lock is available the launcher clears the marker and dismisses the dialog. Activity destruction cancels only that activity's watcher; a later launcher instance resumes checking the marker. Process death releases the OS lock, allowing recovery without relying on a process-local flag.

The native engine library, game files, controller mappings, original save importer and bundled 100% save are unchanged. Display recovery, compact statistics work and remaining touch artwork caching are included in the expanded R2.3 scope. Native frame-stall attribution still needs the affected phone.
